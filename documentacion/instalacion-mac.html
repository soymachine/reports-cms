Poner el dashboard en el Mac de tu hermano

Ocho pasos, de una terminal limpia a la tabla de leads abierta en el navegador. Están en orden: cada uno da por hecho el anterior.

Tiempo 30–45 min (casi todo esperando descargas) Requiere macOS · Apple Silicon o Intel Repo soymachine/reports-cms

Lo que tienes que darle tú

Tres cosas que no viajan en el repositorio. Sin las dos primeras no hay instalación que valga, así que resuélvelas antes de sentarte con él.

  • Acceso El repositorio es privado. Invítale como colaborador en GitHub (Settings → Collaborators) con su cuenta, o tendrá un 403 al clonar.
  • Datos El fichero leads.db, que está en .gitignore porque contiene empresas y contactos reales. Pásaselo por AirDrop o disco. Sin él el dashboard arranca, pero todas las pantallas dan error.
  • Opcional Las carpetas pdfs/ y generated/ si quieres que vea el trabajo ya hecho. Son unos 300 MB y también están fuera de git.

Para lo que él va a hacer, no necesita Magnific. Subir pares antes / después hechos a mano y sacar el PDF comparativo funciona sin cuenta de Magnific, sin Hermes y sin gastar un solo crédito. La generación con IA es la única parte que los pide, y va al final como paso opcional.

Los ocho pasos

  1. 01

    Fusiona la rama a main

    en tu Mac

    Todo lo nuevo —los pares a mano incluidos— vive en una rama con ocho commits que main no tiene. Si clona main tal y como está hoy, se llevará una versión sin la función que necesita.

    Terminal · tu Mac
    # desde la carpeta del proyecto en tu ordenador
git checkout main
git merge claude/before-after-improvements-nbpstf
git push origin main

    Si prefieres no tocar main todavía, sáltate este paso y que él clone la rama directamente: se indica en el paso 4.

    Comprobación git log --oneline -1 origin/main muestra el último commit de la rama, no «Primer commit».
  2. 02

    Herramientas de desarrollo de Apple

    en su Mac

    Trae git y el compilador. Hace falta para Homebrew y para que npm pueda construir la pieza nativa de la base de datos si no encuentra binario ya hecho para su Mac.

    Terminal
    xcode-select --install

    Se abre una ventana del sistema: aceptar y esperar. Si ya estaban instaladas, responde que no hay nada que hacer y sigues igual.

    Comprobación git --version responde con un número.
  3. 03

    Homebrew

    en su Mac

    El gestor de paquetes con el que se instala todo lo demás.

    Terminal
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

    Al terminar, el instalador imprime dos líneas eval "$(...brew shellenv)" bajo un aviso de Next steps. Hay que copiarlas y ejecutarlas, o brew no existirá al abrir la siguiente terminal.

    Comprobación brew --version responde.
  4. 04

    Node, Python y las dos herramientas de imagen

    en su Mac

    Una sola orden. poppler convierte las páginas del PDF en imágenes —es lo que hay detrás del botón «Ver páginas»— y tesseract lee las cifras del rediseño para comprobar que no se ha perdido ninguna.

    Terminal
    brew install node python@3.12 poppler tesseract
    Comprobación las cuatro responden: node --version (v22 o superior), python3.12 --version, pdftoppm -v, tesseract --version.
  5. 05

    Clonar el proyecto

    en su Mac

    La carpeta puede ir donde quiera; aquí va en ~/Trabajo.

    Terminal
    mkdir -p ~/Trabajo && cd ~/Trabajo
git clone https://github.com/soymachine/reports-cms.git
cd reports-cms

    GitHub le pedirá su usuario y un token de acceso personal —no la contraseña de la cuenta—. Si te saltaste el paso 1, que se cambie ahora a la rama:

    Terminal · solo si no fusionaste
    git checkout claude/before-after-improvements-nbpstf
    Comprobación ls dentro de la carpeta muestra dashboard, scripts, settings.json y start.command.
  6. 06

    El entorno de Python

    en su Mac

    El dashboard llama a los scripts de Python por una ruta fija, .venv/bin/python dentro del proyecto. Tiene que crearse ahí, con ese nombre.

    Terminal · dentro de reports-cms
    "$(brew --prefix)/bin/python3.12" -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install openpyxl pymupdf pillow pytesseract
    Comprobación .venv/bin/python -c "import openpyxl, pymupdf, PIL, pytesseract; print('ok')" imprime ok.
  7. 07

    Copiar la base de datos

    de tu Mac al suyo

    leads.db va a la raíz del proyecto, al lado de settings.json. Es el único fichero imprescindible que no está en git.

    Antes de copiarlo, cierra el dashboard en tu Mac. SQLite deja ficheros leads.db-wal y leads.db-shm con cambios todavía sin volcar; si copias la base con el servidor abierto, puede llegarle incompleta.

    Si además quieres que vea los reports y los rediseños ya hechos, copia las carpetas pdfs/ y generated/ enteras al mismo sitio.

    Comprobación ls -lh leads.db desde la raíz del proyecto muestra un fichero de varios cientos de KB o más.
  8. 08

    Arrancar

    en su Mac

    Doble clic en start.command desde el Finder, o desde la terminal:

    Terminal · dentro de reports-cms
    ./start.command

    La primera vez instala las dependencias del dashboard —tarda unos minutos y no dice gran cosa mientras lo hace— y luego abre solo http://localhost:4321. Para pararlo, Ctrl+C en esa ventana. Mientras esté abierta, el dashboard funciona.

    Comprobación el navegador abre la tabla de leads con datos. Eso significa que Node, la base de datos y el servidor están bien.

Probar que está todo, no solo que arranca

Que cargue la tabla solo demuestra media instalación. Estas tres pruebas tocan cada una una pieza distinta, y son justo el camino que él va a recorrer cada día:

Abrir un lead con PDF y pulsar «Ver páginas»
Si aparecen las miniaturas de las páginas, poppler está bien instalado.
«Pares a mano» → subir un original y una imagen nueva
Si la pareja aparece en Antes / Después como un estilo más, el circuito completo funciona. Si el par sale marcado con «sin QC», falta tesseract.
Pulsar «PDF comparativo»
Si se descarga el deck con la portada de Think Things, PyMuPDF y las tipografías están en su sitio.

Opcional: generar con Magnific

Solo si va a rediseñar con IA en lugar de a mano. Necesita el CLI de Hermes instalado y una sesión de Magnific abierta en su usuario:

Terminal
hermes mcp login magnific

El dashboard lee esa sesión de ~/.hermes/mcp-tokens/magnific.json. Los créditos se cargan a la cuenta que haga el login, así que decidid antes si va con la vuestra o con una suya.

Lo que no va a funcionar en su Mac

Dos cosas, y es mejor que lo sepa antes de buscar el fallo donde no está:

El botón «Lanzar el agente ahora»
Ejecuta una tarea programada de Hermes que vive en tu ordenador, identificada por un id concreto. En el suyo no existe.
Generar rediseños sin el paso opcional
Sin sesión de Magnific la generación falla con un aviso de autenticación. Todo lo demás —pares a mano, comparador, deck, email— sigue funcionando.

Dos ordenadores, dos bases de datos. No hay sincronización de ninguna clase: en cuanto los dos trabajéis sobre vuestra copia, se separan y no hay forma automática de juntarlas. Decidid quién manda sobre leads.db — lo más simple es que sea tuya y que él trabaje sobre una copia para sus rediseños, o al revés, pero no las dos a la vez.

Si algo falla

Todas las pantallas dan error y la tabla sale vacía
Falta leads.db en la raíz del proyecto, o está en otra carpeta. Tiene que estar junto a settings.json.
macOS no deja abrir start.command
Clic derecho sobre el fichero → Abrir → Abrir de nuevo en el aviso. Si dice que no tiene permisos: chmod +x start.command.
npm install falla compilando better-sqlite3
Le faltan las herramientas del paso 2: xcode-select --install y volver a lanzarlo.
«Ya hay un servidor escuchando en el puerto 4321»
Hay otra ventana del dashboard abierta. Ciérrala, o arranca en otro puerto: PORT=4322 ./start.command.
Los pares salen siempre con «sin QC»
Falta tesseract (paso 4) o alguno de los paquetes de Python (paso 6). No rompe nada: solo deja de comprobar las cifras.
«Ver páginas» no muestra nada
Falta poppler (paso 4). Comprueba con pdftoppm -v.
