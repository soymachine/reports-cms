Guía de traspaso

ThinkThings en tu Mac

Montar el CMS de leads en una máquina nueva, de cero a dashboard funcionando. Los pasos van en orden: cada uno da por hecho el anterior.

Tiempo estimado: 40 min macOS · Apple Silicon Actualizado 20/08/2026
Haz clic en el número de cada paso para tacharlo. Se guarda en este navegador, así que puedes cerrar y seguir mañana.
01

Herramientas del sistema

Cuatro cosas, y ninguna es opcional. Si ya tienes Homebrew, empieza por la segunda línea.

# Homebrew, si no lo tienes /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)" brew install python@3.12 node poppler git

poppler trae pdftoppm y pdfinfo, que son los que convierten los PDF en imágenes. Node tiene que ser 22 o superior: compruébalo con node -v.

02

Clonar el proyecto

git clone https://github.com/soymachine/reports-cms.git cd reports-cms

Elige una carpeta donde no te moleste: el proyecto crecerá con los PDF descargados y las imágenes generadas, y llega a ocupar varios gigas.

03

Instalar dependencias pendiente · fase 6

Cuando exista setup.command, esto será un doble clic desde el Finder. Mientras tanto, a mano:

# entorno de Python /opt/homebrew/bin/python3.12 -m venv .venv .venv/bin/pip install openpyxl # dependencias del dashboard npm --prefix dashboard install

Todos los scripts se ejecutan con .venv/bin/python, nunca con el Python del sistema. El dashboard lo resuelve solo.

04

Traer la base de datos pendiente · fase 6

Ni leads.db ni los PDF viajan por git: son datos, no código. Llegarán en un paquete aparte (thinkthings-datos.tar.gz) que se descomprime en la raíz del proyecto.

./scripts/import_bundle.command ~/Downloads/thinkthings-datos.tar.gz
No copies leads.db a pelo con el dashboard abierto en la otra máquina: SQLite en caliente puede dar un fichero corrupto que parece correcto hasta que falla. El paquete se genera con el dashboard parado y trae su suma de verificación.
05

Autorizar Magnific listo

Es lo único que necesita internet y una cuenta. Sin esto todo funciona salvo generar rediseños.

.venv/bin/python scripts/magnific_login.py # para comprobar más adelante si la sesión sigue viva .venv/bin/python scripts/magnific_login.py --status

Se abre el navegador, autorizas y la sesión queda guardada en ~/.thinkthings/magnific/. Se renueva sola a partir de ahí.

Haz tu propio login: no copies los ficheros de sesión de la otra máquina. El token de refresco rota en cada renovación, así que dos máquinas compartiendo sesión se echan la una a la otra.
06

Arrancar listo

Doble clic en start.command desde el Finder, o:

./start.command

Abre localhost:4321 en el navegador cuando el servidor responde. Para pararlo, Ctrl+C en esa ventana. Si el puerto ya está ocupado, no arranca una segunda instancia: reutiliza la que hay.

07

Comprobar que todo está en su sitio listo

.venv/bin/python -m pytest tests -q npm --prefix dashboard run build bash tests/smoke_api.sh

Lo primero prueba la lógica del pipeline, el control de calidad y el cálculo de créditos. Lo segundo es la verificación que hay que pasar siempre antes de dar por bueno un cambio en el dashboard. Lo tercero necesita el servidor arrancado.

08

El cazador nocturno listo

Busca organizaciones nuevas cada noche y las mete como leads sin contactar. Se instala una vez:

./scripts/install_hunter.command

En tu máquina saltará a las 03:30 (en la otra a las 02:00, para que no compitan). Se controla desde el dashboard, no desde la terminal:

  • Cazar ahora — lo lanza al momento.
  • Detener — aborta la ejecución en curso.
  • Cazador activo — interruptor que decide si vuelve a saltar. Apagado, el programador sigue disparando pero el script sale de inmediato.

Los leads que trae entran con origen agent y estado Not contacted: revísalos antes de gastar créditos en generar nada.

·

Si algo falla

SíntomaQué pasa
El dashboard sale en negro Alguien movió las variables CSS dentro de @layer base en global.css. Tienen que estar en la raíz.
«Magnific requiere login» La sesión caducó sin poder renovarse. Repite el paso 05.
pdftoppm: command not found Falta poppler: brew install poppler.
Los PDF no se descargan El buscador usa DuckDuckGo Lite y es sensible a cambios de HTML. Prueba otro lead antes de dar por rota la máquina.
Una generación se queda colgada La cola registra el pid y permite cancelar desde el panel; los trabajos huérfanos se cierran solos al reiniciar el dashboard.
Leads duplicados Normal si el cazador corre en las dos máquinas. .venv/bin/python scripts/dedupe.py los agrupa.
Los pasos marcados como pendientes dependen de la migración que quita Hermes del proyecto — ver migracion-sin-hermes.md. Reglas del proyecto y detalle de cada script: Instructions.md y README.md.
